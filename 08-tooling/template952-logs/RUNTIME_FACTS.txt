How this line's page runs code today, and what the chapter library of chapters 6, 7 and 8 needs (read from template 9.50.0 = 9.52.1, measured 2026-10-23 with Playwright 1.56.0, Chromium, on the scratch page of chapter 10)
1. CPython compiled to WebAssembly (Pyodide 0.28.2) in a Web Worker, loaded from the jsdelivr CDN on the first Run (network needed). Fallback without workers: Brython 3.14.3 on the page thread (no wheels). A run still going after 15 s ends the worker. The code is parsed with ast, the last expression is printed with repr(), stdout/stderr are captured, input() reads the Input lines box.
2. A chapter library reaches the worker through the page data: pywheels_vX.json of the chapter's page folder names wheels (embedded as hex, py_wheels), Pyodide packages (py_packages) and a boot snippet (py_boot), supported since template 9.43.0. Chapters 6, 7 and 8 of this line have NO pywheels file.
3. The deck code of chapters 6, 7 and 8 (ch06-deck/examples_v2_0_0.py, ch07-deck/examples_v1_0_0.py, ch08-deck/examples_v1_0_0.py) imports only the standard library (copy, random, collections.Counter, json, pprint, typing, re); the one shared base module of chapter 8 (sen0414_ch08_corpus_base_v1_0_0.py) only holds the TEXT of whole programs, and the programs are run as separate processes (python -c) by the deck tooling, which a browser cannot do. So no wheel is needed for them; a chapter-code example must be a self-contained console cell group or program text run by the page's own runner, and a program that reads input() takes its lines from the Input lines box. A program that needs files writes them first (the page's Pyodide has a writable in-memory file system).
4. The chapter-code tab (data-pane="chaptercode") uses the same runPy(), so an example runs exactly as a Playground program with the same boot. Measured: a scratch example "Write and read a file" ran in 5.7 s on first use (Pyodide start-up included) and showed "same result as on the slide".
