## Scheme
1. ONE set version for what is delivered to the Owner. The first delivery (mock_exam_v1_0_1.html, CME 166f0dc) is set v1.0.1 and stays as delivered. The linked version (concept links) is set **v1.1.0** (minor: a backwards-compatible addition). Later changes bump the set version.
2. Delivered files carry the set version and the part name, in the convention of the real exam set: `sen0414_mock_exam_v1_1_0_page.html` (the self-contained page), `sen0414_mock_exam_v1_1_0_data.json` (the data the page embeds), `sen0414_mock_exam_v1_1_0_bank_report.json`, `sen0414_mock_exam_v1_1_0_concept_links.json`, and `MANIFEST_SHA256.txt` + `SHA256.txt` in the folder `04-assessment/mock/release_v1_1_0/`. The page shows its set version on the start screen (one small line, e.g. 'mock set v1.1.0').
3. `release_v1_1_0/RELEASE_PARTS.json` is the part table: every component that went into the set with its own identity, version, SHA-256 and source commit (author files A, B, C, D per block, validators, vocabulary, assembly tool, build script, template, page test, exclusion index version by hash only). Part versions stay what they are (each identity has its own version line); the set version says which part versions belong together.
4. One current file per identity in the working folders: every superseded part version moves with `git mv` into `04-assessment/mock/archive/` and `04-assessment/exams/archive_mock/` (never deleted; git history keeps it too), and `ARCHIVE_RECORD.tsv` in each archive folder has one row per file: file, SHA-256, superseded_by, reason, date, set version in which it was archived. No name may say draft, patch, extension, follow-up or copy.
5. The first delivery is archived as `archive/release_v1_0_1/` with its page and data file unchanged.
